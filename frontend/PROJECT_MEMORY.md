## Design system — locked: Swiss Modernism 2.0 x Minimalist Monochrome
- **Zero border-radius, no shadows, no gradients, no glass.** Hairlines + hard rules carry structure. 3.2% SVG paper-grain overlay. Typography IS the interface.
- `WHITE = SPACE / BLACK = STRUCTURE / RED = SIGNAL`. `--color-paper #fff` · `--color-ink #000` · `--color-signal #ff2d16` (large type/graphics only, 3.7:1) · `--color-signal-ink #d91a05` (small red text, AA) · `--color-ash #6b6b6b` · `--color-hair #e4e4e4`. Red stays scarce.
- **Archivo variable: the `wdth 62..125%` axis IS the art direction**, driven with `font-stretch`, NEVER `font-variation-settings`. `.ts-display` (wdth 92) · `.ts-display-tight` (78, giant statements) · `.ts-display-wide` (118, wordmark) · `.ts-body` (100). **JetBrains Mono = `.ts-label`** microcopy, min 11px. Fonts self-hosted — **never reintroduce a Google Fonts link** (CDN is blocked in some environments and the site fell back to Arial, killing the width axis).
- **Zone system:** every section declares `data-zone="paper"|"ink"`, which re-points the whole shadcn token contract. Prefer adding a zone over hand-colouring a component.
- Section padding is owned by exactly 3 utilities: `ts-act`, `ts-act-sm`, `ts-act-open`.
- **No fabricated proof anywhere** (no testimonials/logos/metrics/years). One full-bleed red moment: `FinalCta` on Home, black text on signal — do not invert. **Only ONE real ScrollTrigger pin site-wide** (Home horizontal act); every later "pin" is CSS `position: sticky`.

## Motion architecture
- `lib/gsap.js` is the single plugin-registration point — **always import gsap from there.** Cleanup via `useGSAP({ scope })`; a raw `ScrollTrigger.create` must return a kill.
- `layout/SmoothScroll.jsx`: Lenis `duration 1.05`, custom expo, `syncTouch:false`, **`autoRaf:false`** (GSAP's ticker drives `lenis.raf`, so the two never run on separate RAF loops — that mismatch is what causes pin jitter), `lenis.on("scroll", ScrollTrigger.update)`. Never instantiated under reduced motion. Exposes `{lenis, stop, start, scrollTo}` via `useSmoothScroll()`.
- **Five load-bearing rules, each of which cost a real bug:**
  1. Never animate `yPercent`/`scaleX` **to** a value whose start comes from a CSS percentage transform — the browser resolves it to a matrix and the unit is gone. Use `fromTo`, or `gsap.set` first.
  2. **Never put a Tailwind `scale-*`/`translate-*` utility on a GSAP-transformed element.** v4 compiles them to standalone properties that *compose with* `transform`, so the tween runs and nothing moves. State rest as inline `transform`.
  3. **Never tween a `clip-path` string.** Tween `{w,h,r,o}` numbers and compose the string in `onUpdate` — computed values normalise to shortest form and GSAP pairs complex-string numbers positionally.
  4. **Overlay/portal motion is CSS keyframes, not GSAP** (mobile menu sheet, veil, interior stagger). Radix `<Portal>` renders null until its own layout effect, so `open` never sees the node; and a CSS animation starts at first paint *after* mount while `useGSAP` runs *before* it — 107ms of measured drift. The `[data-state="closed"]` keyframes are load-bearing (Radix `Presence`), and reduced motion needs its own `animation-delay: 0ms`.
  5. **Never `setState` on a pointer or scroll frame.** Write `textContent` / transforms imperatively.
- **Nav zone detection** hit-tests what is actually painted: `document.elementsFromPoint(innerWidth/2, 28)` -> skip header nodes -> `closest("[data-zone]")`, on ScrollTrigger update plus a `gsap.ticker` sample every 4th frame (the pin applies *after* onUpdate). **Do not "simplify" it** — per-section triggers and a live `Set` were both tried and both flickered.
- **Mouse follower `layout/Cursor.jsx`:** ONE fixed `340x96` box, and every state is a `clip-path` window onto it — idle 30sq, interactive 58sq, labelled 96sq, capsule measured-width x54 r27. Two plates: the outer paper-white window is the inner grown 1.5px, so white reads only as a rim. Nested `data-cursor` resolves nearest-first (labels include `scroll`, `explore`). Guard morphs on a state key: `pointerover` bubbles and fires for elements sliding under a *stationary* pointer (the hero marquee did this continuously). Kill the copy timeline by hand — `overwrite` is silently ignored on a timeline. **Hero words must never fade on hover** (user decision). Live only on `(pointer:fine) and (hover:hover)` and not reduced-motion.
- `motion/` holds the React Bits ports: `ProximityType`, `Magnet`, `CurvedMarquee`, `SignalField`, `EdgeWipe`, `ScrambleText`, `CutoutHeading`, `FieldLines`. **Precedent: React Bits components are rewritten, never shipped verbatim** — each arrived with a Google-Fonts import, a private RAF loop, per-event `getBoundingClientRect`, or colliding global class names. `ProximityType` activates on **hover** (`HOVER_PAD` 6px, keep it small), not proximity.
- Before adding any new top-level class, diff it against `index.css` — `.ts-field` collided with the contact form and re-laid every input into 13 columns.

## /capabilities — the desktop-only experience (current focus)
CAPABILITIES on paper + lens + intent ImageTrail -> HUMAN and MACHINE hands approach -> fingertips meet, one red square -> aperture opens out of that square -> RAW. becomes REFINED. under the pointer -> BEAUTY IS ONLY THE SURFACE. -> aircraft scrubbed by scroll, forward and back. **One continuous piece.**

Files in `src/components/capabilities/`; stylesheet `src/styles/capabilities.css` is imported by `CapabilitiesExperience` so it lands in THAT chunk, not index.css: `pages/Capabilities.jsx` (device gate + dynamic-import boundary) · `useCapabilityDevice.js` · `CapabilitiesRestricted.jsx` · `CapabilitiesExperience.jsx` (orchestrator) · `capabilitiesStage.js` (store: `set`/`subscribe`/`republish`) · `capabilitiesAssets.js` (every path, `BEATS`, `CONTACT_FY`, `LOAD_STAGES`, `TRAVEL`, `INTENT_TRAIL`) · `usePointerLens.js` · `ImageTrail.jsx` · `OpeningScene` · `HandsScene` · `SneakerScene` (aperture + RAW/REFINED) · `AircraftScene` · `CapabilitiesOutro`.

- **Two sticky stages, not seven sections.** Act 1 (`TRAVEL.act1` 760svh) holds opening + hands + contact + aperture + sneaker as **layers in one stage** — that is what makes the aperture spatial rather than a page turn: the sneaker world is genuinely already mounted and painted underneath the hands, and the circle only decides how much shows. Act 2 (520svh) opens on the same near-black act 1 closes on, so the seam between the two stages cannot be seen. The pin is CSS `position: sticky`; ScrollTrigger only *reports* progress.
- **One clock, two numbers:** GSAP ticker -> Lenis -> `ScrollTrigger.update` -> two triggers write `act1`/`act2` into the store -> every scene reads them. **No component on this page starts its own RAF**, and no scene derives a scroll position independently. `store.republish()` fires on every gate change, because the scenes are gated and a gate flip is not a scroll event (it showed up as the hands beat arriving at opacity 0).
- **FINGERTIP ALIGNMENT — never "fix" this by animating both plates to centre.** Plates are 1672x941 and the tips were *measured*: human px (1047, 416.0) -> `x .62620 y .44208`; robot px (639, 362.5) -> `x .38218 y .38523`. The two y values are 5.7% of plate height apart, so centring misses at every viewport by a different amount. Each plate is instead placed in **CSS** so its own tip lands on the contact point, and JS animates **only `x`**; `top` is derived from a width via container-query units (`cqw`, needs `container-type: size`). Verified dy <= 0.02px at 1280-2560 and 0.00 after live resizes. `CONTACT_FY = 0.47` is declared once and consumed by both the CSS and the aperture centre — they must not drift. **`max-width: none` on `.cap-hand` and `.cap-lens-img` is load-bearing:** Tailwind preflight's `img{max-width:100%}` clamps the deliberately 106%-wide plate and silently moves the fingertip. Character: the robot is strictly linear; the human runs `LEAD 5.5%` ahead and lifts `DRIFT -9px`, both shaped by `sin(pi*p)` so they are zero at both ends and cost the alignment nothing.
- **`usePointerLens` — used twice (opening + sneaker).** NOT a moving `clip-path: circle()`, which re-rasterises what it clips every frame. A fixed-size window whose shape never changes, with a copy of the content counter-transformed to stay welded to the viewport: window `translate+rotate+scale`, inner `rotate(-theta) scale(1/sx^r)`, frame `translate(-pointer)`. At `r=1` the two compose to a pure translation — a real hole in the page; **refraction is the deliberate under-correction** at `r<1`. One damped follow produces everything: the window's own frame-to-frame delta (not the raw pointer) is the velocity driving squash, rotation and growth, so the shape settles by itself. **Clip the window shape on `.cap-lens`, not the inner** — the inner is counter-*rotated*, and clipping there rendered a spinning octagon; use `radial-gradient(circle closest-side)` + `mask-repeat:no-repeat`. The dispersing rim `.cap-fringe-r/g/b` are children of the **window** so local +x is already the heading (no trigonometry), with `mix-blend-mode: screen`. **`onEnergy`/`wake`/`options` must stay in refs** — in the dependency array the hook tore itself down on the very state change its own callback caused. Neither interaction uses React state at all.
- **Opening beat:** white paper, one word, rendered **white with `mix-blend-mode: difference`** so it reads black on the paper and flips white wherever the lens puts dark behind it — one blend layer does the whole inversion, with nothing to keep in sync. Reveal image `reveal-bg` (a visor with a galaxy) is sized 1.08x the stage so refraction can never pull a picture edge into the window.
- **ImageTrail** (rewritten from React Bits) rides the same five `/intent` pictures `/contact` uses, cut to 440px into `optimized/intent/img1-5.{avif,webp}` (102.5 KB AVIF). RAF-free — it runs on `gsap.ticker`, is distance-threshold gated, derives `MIN_GAP` from `LIFE`/`MAX_ACTIVE`, wipes in with a clip-path, and takes the **same `active` flag as the lens** plus a `quietRef` on the title so the trail never overwhelms the type.
- **Aperture:** `clip-path: circle(R at cx cy)` on `.cap-world`, centred exactly on the contact point, radius eased 0 -> far corner, with `will-change: clip-path` written only while it moves. The scaled-disc alternative was rejected: it starts near scale 0, which puts its content at a counter-scale in the hundreds.
- **RAW -> REFINED:** same box, not side by side. RAW is the ground; REFINED sits above it inside the lens window and is **uncovered, never faded in** — a crossfade between two shots of the same object goes to mush in the middle. Both files were cut from identical 240-frame / 24fps / 10.006s masters. RAW is the master; REFINED corrects small drift by **`playbackRate` +/-6%** and only >0.34s by a seek (a seek drops a frame and lands with its own latency, so a tight threshold stutters *and* drifts anyway). Checked 4x/second; measured max drift 18.6ms. `.cap-word-swap` must stay a **one-cell grid** — absolute positioning took the second word out of flow and clipped "REFINED." to "REFII".
- **Aircraft:** `optimized/aircraft.mp4` is **all-intra (`-g 1`) — 240 keyframes in 240 frames** — so a backward seek costs exactly what a forward one does. This is the re-encode /lab's notes predicted, and it retires the WebCodecs path entirely. **No interpolation:** Lenis has already smoothed the scroll before ScrollTrigger reports it, and easing an eased value a second time is exactly what produces "scroll stops, picture keeps going" — `follow = 1`, written on the tick it is computed. Frames are targeted at their **centre**, `(frame + 0.5) / fps`. The decoder is woken with a `play()`/`pause()` pair at stage 5, because a `<video>` that has only been preloaded has no decoder allocated and its first frame can take seconds. **`/capabilities` does not use ScrollyVideo** — that is /lab.
- **Device gate** (`useCapabilityDevice`) — three independent questions, all required: `(pointer:fine) and (hover:hover)` (the load-bearing one — it describes the input device, so every phone fails it in *both* orientations), `min-width: 1024px`, and short viewport edge >= 620px. It returns `null` until decided, and the heavy experience sits behind `lazy()` **below** it, so a phone requests **zero** heavy assets. That is why it is not a CSS `display:none` — a hidden desktop tree would still cost the phone both videos and both plates. **Do not build a mobile version of this page.**
- **Staged loading** (`LOAD_STAGES`, at act1 progress): 1 @0 hands mounted · 2 @0.26 sneaker `preload=metadata` · 3 @0.46 sneaker `auto` · 4 @0.66 aircraft `metadata` · 5 @0.80 aircraft `auto` + decoder woken. Stages 4/5 sit earlier than they originally did because the aircraft file grew — the runway has to grow with the bytes (256svh of travel before the first frame is needed). Stages never go backwards.
- **Prepare gate:** reveal image + both hand plates + `document.fonts.ready` — three units of genuinely resolved work, no invented percentage, capped at **2500ms** so the page can never sit behind its own loader. Scroll is held with Lenis (never by swallowing wheel events) and only ever at the very top, so returning mid-scroll cannot freeze under anyone.
- **Offscreen:** sneakers pause and their sync loop stops, the aircraft pauses, both lenses remove their listeners **and** their ticker callbacks, and every `will-change` is cleared on exit rather than left on.
- **Reduced motion is a *still* page, not a stripped one:** acts collapse to `height:auto`, the stage becomes a flex column, the aperture is already open, both lenses and the rim are `display:none`, every video is paused, and the sneaker resolves to its **answer** (raw dropped, refined promoted out of the lens to fill the frame). Flex `order` restores the narrative sequence, because while pinned, source order is z-order. Act 2 is targeted by `.cap-layer-air`, **not `:last-of-type`** — the acts are not the last sections on the page, so `:last-of-type` selects the outro.

| shipped | size | note |

| `aircraft.mp4` | **6.27 MB** | **all-intra CRF 21**, 5,258 kbps, `-x264-params aq-mode=3:aq-strength=0.9:deblock=-1,-1`, preset veryslow |
| posters (frame 0, avif+webp) | 14.8 / 19.4 / 17.0 KB | nothing on this page ever presents an empty stage |

All video: `-an`, yuv420p, profile high, `-sc_threshold 0`, `+faststart`, and `delogo=x=1130:y=568:w=64:h=64` — all three sources carried the same generator sparkle at (1161,600), always on plain studio falloff, so the interpolation leaves nothing behind. **No WebM:** both jobs depend on guaranteed hardware decode and H.264 is the one codec that gets it everywhere.

**AIRCRAFT QUALITY — settled, do not re-litigate.** The softness was CRF 28, not the resolution, upscale, poster, or source. All-intra discards every bit of temporal prediction, which on near-identical frames is most of the available compression, so it needs far more bits per frame. Measured PSNR-Y / SSIM-Y against the delogo'd source plus browser seek latency (headless = software decode = worst case): `g1 crf28` 3.43MB / 38.10dB / p50 14ms -> **`g1 crf21` 6.27MB / 42.37dB / p50 20ms / worst 46ms** (chosen). The small-GOP rows are a trap: `g8 crf19` is 3.99MB at 46.60dB but p50 **39ms** / worst 117ms — at 60Hz that is the picture 2.5 frames behind the scroll on every step. **The source is 1280x720 and there is no larger master**, so the full-bleed stage upscales 1.25x-2.5x and the softness that remains at 100% zoom is the source's; a 1080p derivative would only move the resampling from the browser's scaler to ffmpeg's at 3x the bitrate.

Desktop first load 340 KB (route chunk 3.14 KB + experience 21.5 KB JS + 8.1 KB CSS + reveal image + both plates + fonts). A phone loads 128 KB and stops.

## Backend (Phase 2, live)
`POST /api/contact` · `GET /api/health` · `POST /api/auth/login` · `GET /api/auth/me` · `POST /api/auth/logout` · `GET /api/admin/stats` · `GET|PATCH /api/admin/inquiries*`.
- `requireAuth` is applied with `router.use("/admin", ...)`, so a new /admin route is protected by default. `/auth/logout` is deliberately **not** protected — an expired session must still be able to clear its own stale cookie.
- **The order in `createInquiry` is load-bearing:** `Inquiry.create` -> `res.json(201)` -> *then* send mail. Mail is never awaited before responding and a mail failure never re-runs the write, so a client retry cannot create a second inquiry for one real message. `mailer.js` **never rejects** — it resolves a result recorded on the row as `mail.{customer,internal}`.
- `purpose` is optional with default `"General Inquiry"`: the live form has only name/email/message and the Contact UI was to be preserved.
- JWT in an **HttpOnly** cookie `ts_admin_token`, SameSite=Lax (safe because the app is same-origin — Vite proxies `/api` in dev *and* preview). bcrypt cost 12; `passwordHash` is `select:false`; `requireAuth` re-reads the admin every request so deleting one revokes immediately. Login gives one message for both failure modes and runs bcrypt against a **valid** dummy hash (a malformed one returns false instantly and reintroduces the timing signal). `bootstrapAdmin` is idempotent.
- Frontend auth `status` is a **three-state** `checking|authenticated|anonymous` — treating "unknown" as "signed out" bounces a signed-in admin to login on every refresh. `ProtectedRoute` decides rendering only; `/api/admin/*` is the real boundary.
- Honeypot `website` is moved **off-screen, not `display:none`** (a bot that skips undisplayed inputs would skip the trap), and a trip answers **201 with the ordinary success shape**. `errorHandler` forwards only `AppError` messages; a CORS denial must be `AppError.forbidden` — a bare `Error` became an opaque 500.
- `emailTemplates.js` is table-based inlined HTML in Helvetica/Arial (**no webfont** — it would fail mid-render in most clients), everything through `escapeHtml`. Internal mail sets `replyTo: visitor.email`.
- Dashboard styling is `src/styles/dashboard.css`. **Red means exactly one thing: `NEW`** — the other statuses differ by *fill*, not hue. `position: sticky` needs room in its containing block: `.ts-inq-split` uses `align-items: stretch`, not `start`.
- Env lives in `backend/.env`, documented in `.env.example`; **no secret appears in this file.** `NODE_ENV PORT MONGO_URI JWT_SECRET JWT_EXPIRES_IN ADMIN_EMAIL ADMIN_INITIAL_PASSWORD EMAIL_USER EMAIL_APP_PASSWORD CONTACT_RECEIVER CLIENT_ORIGIN`. `config/env.js` is the only reader; `assertEnv()` fails the boot.
